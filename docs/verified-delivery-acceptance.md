# v4 技術驗收與表演驗收分離

基準：PR #9，延續 Issue #6 與 PR #10 的表演／FilmDSL 規格。這不是另一套影片架構。

## 判定

- NOT_RUN：離線計畫，不是影片。
- BLOCKED：技術驗收不通過、缺片、抽幀／評分服務故障、合片／探測錯誤或時長不符。
- REVIEW_REQUIRED：技術驗收通過，仍須人工檢查完整影片。不得宣稱交付成功。
- 不以 MP4 存在、模型自述或離線測試替代真實成品驗收。

## 第一輪 30 秒／5 鏡／9:16

主題：為什麼記帳總是撐不過三天？核心訊息：降低記錄摩擦，先從一筆有意義的消費開始；不承諾投資報酬。五鏡：疲憊打開記帳介面、看到繁瑣明細、停頓思考、簡化記錄、完成一次記錄。實際文字由後製疊加，不要求模型生成可讀 UI。

人工檢查（每項 0–100，以下門檻待校準）：敘事可理解性 85、表情自然度 80、肢體表演 80、動作因果 85、跨鏡接續 85、視聽同步 80、內容對齊 85。每項需附時間碼與觀察證據；不適用項需說明（例如無對白不評嘴型）。任一適用項未驗或低於門檻不得交付。三張抽幀無法驗證聲音、嘴型或連續演技。

## 執行順序

1. Python 3.10+、ffmpeg、ffprobe，先跑離線測試與 plan/check，不用 --live。
2. 供應商憑證僅放受控環境，先 doctor 查模型能力與額度；doctor 不是付費生成成功證據。
3. 確定可用母圖、模型及使用者同意的費用上限；在無可靠金額閘門前不自動進行多鏡付費測試。
4. 單鏡真實測試先用 --max-retries 0，保留原始 MP4、report、分鏡及 provider 去密證據。生圖不可用時只用已批准母圖 carry；不得悄悄換模型或重送不明結果。
5. 通過單鏡人工檢查再擴到五鏡，完整人工驗收前維持 REVIEW_REQUIRED。TTS／對嘴／多角色表演時間軸仍由 Issue #6 追蹤。

本文件不宣稱已生成影片，也不宣稱已接入真正的表演評估器。
